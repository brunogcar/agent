| **v1.22** | 2026-11-24 | **HARDENING — the adversarial-review wave (money math + store + CSRF).** Four independent reviews of v1.21 converged on the same narrow set of real defects; this release closes the P0/P1 class. **(1) SHORTS COUNT** — `positions()` dropped negative market values from the totals (the `>= 0` filter meant to skip the no-quote sentinel) while keeping their negative cost: a short book showed Patrimônio R$ 0,00 / Lucro +100% (truth: −R$ 1.500 / +14,29% — `directory()`/`overview()` had it right, so the same page showed two Lucros). The `-1.0` sentinel is dead (`_v: None`), and a ticker held LONG in one account and SHORT in another now shows PM/Lucro % as "—" with a 🔀 flag (the blended Σ(qty·pm)/Σqty existed in no broker) — qty/cost/value/profit stay (value−cost is still the per-leg profit sum). **(2) THE STORE NEVER WIPES** — a corrupt/unreadable `webui_portfolio.json` used to become an empty store in memory, and the next mutation SAVED that emptiness (the background metadata thread could trigger it with zero user action; the same pattern was lenient shape-parsing: `{"users": {...}}` silently read as "no users"). Now: wrong shapes raise, the damaged file is quarantined (`webui_portfolio.json.corrupt-<ts>`, newest 7 kept), the last good in-memory store keeps serving reads (the `.bak` of the previous good save boots a fresh start), every save writes that `.bak` first, every mutation is refused with a PT-BR 503 until the file on disk parses again (fix/replace it → mtime changes → self-heals), and `state()` carries `store_error` for a 🚨 banner on the Carteira. Transient `stat()` OSErrors (AV/backup locks on Windows) no longer reset memory; mtime tracking is `st_mtime_ns`. **(3) NaN/±inf are rejected at the `_num()` boundary** — they passed every range comparison (`nan <= 0` is False), persisted as bare `NaN` tokens and poisoned whole accounts. **(4) CSRF closed** — `request.json()` parses ANY content type, so any web page could POST `text/plain` (CORS-simple, no preflight) and create users/txs/watchlist entries on the loopback server. Two layers: the new `CrossSiteGuardMiddleware` (pure ASGI, all routers) rejects cross-site mutations (`Sec-Fetch-Site: cross-site` always; non-loopback `Origin` unless `WEBUI_ALLOW_LAN=1` — curl/SDK clients send neither and pass), and `_json_body` demands `application/json` (forces the preflight the localhost CORS list rejects). Same guard on `PUT /settings`. **(5) DETERMINISTIC REPLAY** — same-second transactions replayed in random uuid order (same trades, different PM/realized: 15,00/−450 vs 10,00/−700). Transactions now carry a monotonic insertion `seq` (backfilled in list order for pre-v1.22 files), the order key is `(date, created_at, seq)` and `_tx_rows` uses the same total order (the 200-cap keeps the newest 200, no reverse-flip). **(6) FLIP FEES** — a buy covering a short and flipping long charged the WHOLE fee to realized and opened the long feeless; the covered share now goes to realized and the excess share enters the new long's PM (short 50@20 → buy 100@10 + R$ 10 fees: realizado 495, PM 10,10 — the "buy fees enter the PM" rule). Sell fees stay in realized (the short-open convention — a flip decomposes exactly into covered-sell + open). **(7) SELL A R$ 0,00 É RECUSADA** (bonificação continua COMPRA a 0 — a blank price field no longer books a −R$ 3.000 phantom realized loss). **(8)** a never-traded/delisted ticker no longer defeats the 30s quote cache (the requested set — found or not — is memoized). **(9) TICKER: ONE DEFINITION** (`webui/validators.py`) — the four drifted copies of `^[A-Za-z]{4,6}\d…` rejected **B3's own ticker (B3SA3)** and BDRs (A1MD34); digits in the stem are legal B3 symbology (strict superset: nothing previously accepted is rejected). **(10) delete-not-found no longer 500s** (`_bad(status=)` vs callers' `status_code=` → TypeError); the service's error payloads can carry their own status (the store's 503 surfaces correctly). **(11)** `update_tx` refuses moving a transaction to ANOTHER USER's account (silent cross-user sums), and edits/deletes that leave shorts open return `warnings` the UI shows as a ⚠️ note (per-account replay before/after). **(12) parseBr paste**: "3.65"/"0.0432" (one dot, no comma, not a thousands group) read as US decimals — the old strip-the-dot read 365 (100×); "1.234" stays PT-BR thousands. `?v=66`. |
