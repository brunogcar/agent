# 🧠 B3 Skills

Analytical skills that combine B3 market data sources with domain reasoning.

**Key characteristics:**
- **Read-only** — no sync. Skills call data_source query engines directly.
- **Sync guard integration** — every B3 skill declares `required_sources` (e.g., `["index"]`) in `__init__.py`. The `route()` wrapper calls `ensure_fresh()` before dispatch.
- **Combine multiple sources** — each skill merges data from B3 sub-domains (api, dividends, brapi, cotahist, index) and optionally CVM (bridge, cad) for cross-domain joins.

## Skills

| Skill | Modes | Data Sources |
|-------|-------|--------------|
| [**index**](b3/INDEX.md) | dashboard, compare, ticker | B3 INDEX (composition + history) + B3 API instruments (sector join) + CVM bridge (ticker→CNPJ when needed) — index analytics |

All B3 skills use `core/br_validator` for BRL/date/ticker parsing.

## 📊 Report Integration (v1.0)

B3 skills return nested JSON. To render or export that data, pipe a skill result
into the `report` tool's `table` action (or `export` xlsx) with the matching
adapter in `config["adapter"]`. The report tool stays domain-agnostic — adapters
live in `tools/report_ops/adapters/`.

```
# 1. Get the data
skill(domain="b3", sub_domain="index", mode="dashboard", params='{"index":"IBOV"}')
#    -> <index dashboard JSON>

# 2a. Render as an HTML table
report(action="table", title="IBOV Dashboard",
       data=<index JSON>, config={"adapter":"index_dashboard"})

# 2b. Or export to Excel
report(action="export", title="IBOV Dashboard",
       data=<index JSON>, config={"format":"xlsx","adapter":"index_dashboard"})
```

| Skill (mode) | Adapter |
|--------------|---------|
| index dashboard | `index_dashboard` |
| index compare | `index_compare` |
| index ticker | `index_ticker` |

Number formatting (BRL, %) is handled by the report tool's shared `formats.py`
spec vocabulary — skills don't need to format anything. See
[tools/REPORT.md](../tools/REPORT.md) and [report API](../tools/report/API.md).

## Quick Start

```
# Index dashboard (IBOV — overview + top constituents + history)
skill(domain="b3", sub_domain="index", mode="dashboard", params='{"index":"IBOV"}')

# Compare 2 indices side by side
skill(domain="b3", sub_domain="index", mode="compare", params='{"indices":["IBOV","SMLL"]}')

# Which indices does PETR4 belong to + weight in each
skill(domain="b3", sub_domain="index", mode="ticker", params='{"ticker":"PETR4"}')
```

## 🔧 Prerequisite Sync Commands

B3 skills are read-only — they need B3 data sources synced first. Run from `D:\mcp\agent>`:

```powershell
# INDEX (index composition + history — needed for all index skill modes)
D:\mcp\agent\venv\Scripts\python.exe -c "from data_sources.b3.index.sync_engine import sync_all; print(sync_all())"

# Optional: B3 API instruments (for sector joins in dashboard)
D:\mcp\agent\venv\Scripts\python.exe -c "from data_sources.b3.api.sync_engine import sync; print(sync(table='instruments'))"
```

See [B3 Data Sources](../data_sources/B3.md) for per-sub-domain details, and [CVM Data Sources](../data_sources/CVM.md) for CVM sync commands (needed by cross-domain skills via the bridge).

## Architecture

```
LLM → skill(domain="b3", sub_domain=..., mode=..., params=...)  [skills/dispatcher.py @tool]
       └→ skills/b3/__init__.py route()
          └→ skills/b3/<skill>/__init__.py route(mode)
             │
             ├─ B3 skills use the modular pattern (index v1.0):
             │    └→ skills/b3/<skill>/modes/<mode>.py  (auto-discovered via _registry.py)
             │       └→ helpers.py + report.py
             │          └→ data_source query engines + calculations engines
             │
             └─ (no legacy single-file B3 skills remain)
```

**B3 skills** use the **modular `modes/ + _registry.py` pattern** (auto-discovery via `importlib` on `modes/*.py`, mirroring `skills/cvm/calculations/_registry.py` + `tools/git_ops/actions/`): `index` (v1.0). Adding a new mode = drop a file in `modes/` + `@register_mode(...)`; no edits to `__init__.py`. Every B3 skill also has a `dashboard` mode + matching `<skill>_dashboard` report adapter.
